## Master closure pass — indexed reads and Push isolation (15 November 2026)

The Push path no longer calls the Expo HTTP transport inside the same Convex mutation that creates inbox/referral records. A transactional `pushDeliveryOutbox` record is scheduled for a separate internal Action, with atomic claim, dedupe by stable event identity, terminal unknown status for ambiguous provider outcomes, an orphaned-claim watchdog, and recovery only for never-claimed pending work. A recurrence-specific delivery identity preserves later legitimate campaign sends while deduping the same run. This provides at-most-one automatic provider attempt per outbox identity, **not exactly-once receipt**, and intentionally may defer an uncertain notification instead of retrying blindly. Tests remain mock-backed, not proof of live Convex and Expo delivery.

Of the original 13 dangerous source findings, five are now code-addressed and locally tested (26, 29, 31, 32, 33). Eight remain open: 20–24, 56–57, and 61. Of 49 original improvement findings, three have been code-addressed and locally tested (18, 25, 39); 46 remain open. Finding 26 uses complete timestamp-indexed bounded legacy/API retrieval for every filter combination, not a silent early scan cap. Finding 39 merges two exact indexed event partitions while preserving event timestamps. New indexes and schema have not been applied to a live deployment.

The form inventory still includes existing-record editors without proven optimistic concurrency protection; no claim of full form closure is made. Automation audience/history reads (52–53) and unbounded discovery remain code issues, not solely device acceptance. Versionless referral enforcement remains off. PR #17 still must be reconciled before PR #18. No merge, production deployment, real charge, or real-data mutation occurred.
